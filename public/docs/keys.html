🗝️ 1. Two-Key Architecture: Gateway Key vs. CometAPI BYOK Key

Plugging your app into CostImplodeAI involves two distinct credentials with clean separation of privilege:

1️⃣ CostImplodeAI Gateway Key

Authenticates your application to https://api.costimplodeai.com/v1. Prefixed with cia_live_... (production) or cia_test_... (sandbox). Controls RPM limits, scopes, and hard monthly spend caps.

2️⃣ Funded CometAPI.com BYOK Key ↗

Authorizes upstream model execution against your own prepaid credits at CometAPI.com (prefixed sk-...). Encrypted client-side in your vault or sent statelessly via x-byok-cometapi-key.

Important: You must purchase credits in CometAPI.com before live requests can execute. Use separate keys per environment (production, staging, CI, local developer laptops) so revoking one never disrupts another.

⚡ 2. Generating & Scoping Gateway API Keys

You can generate gateway keys interactively from the Gateway API Keys dashboard or programmatically via POST /api/v1/keys:

Parameter Recommended Practice Example Value
label Include service name + environment billing-worker-prod
env Use test in dev/CI; live only in prod "live" or "test"
spend_cap Always enforce a monthly hard stop for non-critical workloads "500" ($500/mo ceiling)
scopes Grant least-privilege scopes per microservice ["arbitrage:execute", "models:read"]
create_gateway_key.sh 
curl -X POST https://costimplodeai.com/api/v1/keys \
  -H "Content-Type: application/json" \
  -d '{
    "label": "checkout-agent-prod",
    "env": "live",
    "spend_cap": "500",
    "scopes": ["arbitrage:execute", "models:read"]
  }'

One-Time Raw Token Rule: The server displays the raw cia_live_... token exactly once upon creation or rotation. Copy it straight into your secret manager (GCP Secret Manager, AWS Secrets Manager, HashiCorp Vault, or GitHub Actions Secrets)—never commit it to git or paste it into client-side code.

🔄 3. Zero-Downtime Key Rotation

Rotate production gateway keys every 90 days (and immediately on team offboarding). Our POST /api/v1/keys/rotate endpoint issues a new secret token while preserving your existing keyId, rate limits, spend cap, and cumulative savings analytics.

Zero-Downtime Cutover Pattern (Recommended for High-Availability Services):
  1. Create a secondary key (label: "service-prod-b") with identical scopes and spend cap.
  2. Deploy the secondary key to your secret manager and verify live traffic succeeds in telemetry.
  3. Call POST /api/v1/keys/rotate or DELETE /api/v1/keys on key -a once zero traffic hits the old token.
rotate_gateway_key.sh 
curl -X POST https://costimplodeai.com/api/v1/keys/rotate \
  -H "Content-Type: application/json" \
  -d '{ "keyId": "key_01jh89f0a2" }'

🚨 4. Instant Revocation & Compromised Key Playbook

If a Gateway Key or CometAPI BYOK key is accidentally leaked in logs, build artifacts, or a public repository, execute this sequence immediately:

  1. Revoke the Exposed Gateway Key: Click Revoke in Gateway API Keys or send DELETE /api/v1/keys with {"keyId":"..."}. All subsequent calls with that token are blocked instantaneously.
  2. Revoke & Replace Your CometAPI Key: Log in to CometAPI.com, delete the exposed sk-... key, and generate a replacement key.
  3. Re-Seal the Client Vault: Enter the new CometAPI key into the BYOK Vault, run Test Connection, and click Seal & Encrypt Vault.
  4. Audit Usage Spikes: Inspect GET /api/v1/keys/usage for anomalous RPM or spend spikes during the exposure window.
revoke_gateway_key.sh 
curl -X DELETE https://costimplodeai.com/api/v1/keys \
  -H "Content-Type: application/json" \
  -d '{ "keyId": "key_01jh89f0a2" }'

🛡️ 5. Strong BYOK Entry & Client-Side Security Measures

When you enter your CometAPI.com key on CostImplodeAI, the interface enforces modern security safeguards designed to keep secrets strictly under your control:

  • Format & Whitespace Hygiene: Rejects malformed tokens before transmission and alerts if accidental whitespace or non-ASCII characters are pasted.
  • Auto-Masking on Blur: Key fields automatically revert to masked password inputs whenever you click away, preventing shoulder-surfing leaks.
  • Non-Reversible SHA-256 Fingerprint: Displays a local 12-character hex fingerprint computed inside your browser so you can confirm which key is sealed without exposing plaintext.
  • Client-Side PBKDF2 + AES-GCM-256 Sealing: Keys are encrypted inside your browser via window.crypto.subtle (100,000 PBKDF2-SHA256 iterations, unique 128-bit salt, random 96-bit IV) before syncing ciphertext to the vault.
  • Memory-Only Session Handling: Neither Whop session tokens nor your CometAPI key are persisted in localStorage or sessionStorage.

🔌 6. Plugging Your App Into CostImplodeAI

Store both secrets strictly in server-side environment variables and configure your OpenAI-compatible client:

.env (Server-Side Only — Never Commit) 
COSTIMPLODE_BASE_URL=https://api.costimplodeai.com/v1
COSTIMPLODE_API_KEY=cia_live_replace_with_generated_token
COMETAPI_API_KEY=sk-replace-with-your-funded-cometapi-key
node_sdk_production.ts 
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: process.env.COSTIMPLODE_BASE_URL || "https://api.costimplodeai.com/v1",
  apiKey: process.env.COSTIMPLODE_API_KEY,
  defaultHeaders: {
    // Optional air-gapped passthrough: zero persistent key storage
    "x-byok-cometapi-key": process.env.COMETAPI_API_KEY || ""
  }
});

const completion = await client.chat.completions.create({
  model: "auto",
  messages: [{ role: "user", content: "Summarize quarterly SLA metrics." }]
});

🛡️ 1. Two-Tier Envelope Encryption Architecture

CostImplodeAI implements two-tier envelope encryption conforming to NIST SP 800-38D:

  • Key Encryption Key (KEK): A 256-bit AES master key sealed inside Google Cloud KMS Hardware Security Modules.
  • Client-Side Key Derivation & DEK: Browser inputs derive 256-bit keys using PBKDF2-SHA256 (100,000 iterations + random 128-bit salt) and encrypt payloads via AES-GCM-256 with a cryptographically random 96-bit initialization vector (IV).

🏛️ 2. FIPS 140-3 Level 3 Hardware Security Modules

Server-side vault envelopes are backed by Google Cloud KMS HSM clusters validated under FIPS 140-3 Level 3, enforcing tamper-resistant cryptographic boundaries and strict zeroization.

⚡ 3. Ephemeral Volatile Execution (Zero Disk Storage)

  1. CometAPI BYOK credentials are either passed per-request via HTTPS headers or decrypted transiently inside container RAM.
  2. The upstream TLS 1.3 connection to api.cometapi.com executes with forward secrecy.
  3. Immediately after request dispatch, volatile memory buffers are zeroed; plaintext keys never touch persistent storage or logs.

🚫 4. Zero Prompt Retention & Training Guarantee

  • Zero Model Training: Prompts and responses are never used to train models.
  • Zero Payload Persistence: Neither prompts nor completions are persisted to databases.
  • Session Token Hygiene: Browser sessions keep bearer tokens strictly in JavaScript memory (or SameSite=None Partitioned HttpOnly cookies), never in localStorage.

🔑 5. Single-Supplier CometAPI.com BYOK Isolation

By consolidating upstream inference strictly onto your funded CometAPI.com account, security teams audit one wholesale vendor relationship and enforce per-key RPM + monthly spend caps via Gateway API Key governance.

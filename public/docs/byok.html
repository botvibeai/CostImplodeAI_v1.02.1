🔒 5. Current-Practice BYOK Key Entry & Security

CostImplodeAI enforces modern browser cryptographic hygiene whenever you enter a CometAPI key:

  • No Persistent Token Storage in Browser Storage: Auth session tokens and plaintext BYOK secrets are never written to localStorage or sessionStorage.
  • Strict Format & Fingerprint Check: Keys are validated against the sk-... pattern, auto-masked when focus leaves the field, and summarized via a non-reversible SHA-256 fingerprint preview.
  • PBKDF2 + AES-GCM-256 Envelope Encryption: Your browser derives a 256-bit AES key using PBKDF2-SHA256 (100,000 iterations with a random 128-bit salt) and seals your secret with a 96-bit unique IV via window.crypto.subtle before transmitting ciphertext to the sync endpoint.
  • Zero-Storage Direct Header Mode: Prefer zero vault sync? Pass x-byok-cometapi-key directly per API call; the gateway uses it in transient container RAM and zeros the buffer immediately.

💻 6. 1-Minute SDK Integration

Point any OpenAI-compatible SDK to https://api.costimplodeai.com/v1 with your CostImplodeAI Gateway key (created in the Gateway Keys tab or via POST /api/v1/keys).

python_openai_cometapi_byok.py 
import os
from openai import OpenAI

client = OpenAI(
    base_url="https://api.costimplodeai.com/v1",
    api_key=os.environ["COSTIMPLODE_API_KEY"],
    default_headers={
        # Optional: stateless direct passthrough using your funded CometAPI key
        "x-byok-cometapi-key": os.environ["COMETAPI_API_KEY"]
    }
)

response = client.chat.completions.create(
    model="auto",
    messages=[
        {"role": "system", "content": "You are a senior software architect."},
        {"role": "user", "content": "Design a resilient queue consumer."}
    ]
)

print(response.choices[0].message.content)
